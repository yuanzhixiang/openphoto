# Git ignore rules (.gitignore)

## Responsibility

Lists the files the repository doesn't track: build output and local files created by editors and the operating system.

## Behavior

- `/target`: only the Cargo build output directory at the repository root (the workspace shares one target).
- `/dist`: the release packages `scripts/package-macos.sh` writes (e.g. `dist/OpenPhoto-<version>-macos-universal.zip`).
- `.DS_Store`: macOS Finder metadata files at any level.
- `.idea/`: JetBrains IDE configuration directories (any level).
- `.vscode/`: VS Code configuration directories (any level).

## Edge cases

- `Cargo.lock` is not ignored and is committed: the repository contains an executable, so dependency versions are locked for reproducible builds.
- `spec/` is part of the repository and tracked like the source (see the root `CLAUDE.md`).

## Relation to other modules

- Works alongside `.git/info/exclude`: `.gitignore` holds the rules everyone shares, the exclude file each machine's local ones.

## Known limitations

- Only the JetBrains and VS Code configuration directories are covered; local files from other editors or tools are not ignored.
